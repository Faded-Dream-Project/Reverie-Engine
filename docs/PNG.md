# PNG support

Reverie decodes and encodes PNG images with its own codec (`src/png.c`) on
top of its own DEFLATE inflater (`src/inflate.c`). Nothing from libpng,
zlib, or any external command-line utility is involved — scene image
layers, theme assets (loose or inside `.revpack` containers), and
`revtool` asset generation all use this one code path.

## Decoding — what is supported

| Feature | Support |
|---|---|
| Color types | 0 (gray), 2 (RGB), 3 (palette), 4 (gray+alpha), 6 (RGBA) |
| Bit depths | 1, 2, 4, 8, 16 — each only where the PNG spec allows it |
| Adam7 interlacing | Yes, all color types and depths |
| Filters | All five (None, Sub, Up, Average, Paeth) |
| Transparency | tRNS palette alphas, gray/RGB color keys (native depth) |
| Multiple IDAT chunks | Yes, concatenated in order |
| CRC verification | Every chunk; mismatch rejects the file |
| zlib Adler-32 | Verified on the inflated IDAT stream |

16-bit images are reduced to 8-bit by keeping the high byte (the standard
"floor(x / 257)" reduction in the common case). Sub-byte gray values are
scaled by the exact factor (1→255, 2→85, 4→17).

Output is straight-alpha RGBA8 regardless of input form.

## Decoding — what is NOT supported (and what happens)

* **Color management** — gAMA, sRGB, iCCP, cHRM are skipped. Images are
  interpreted in the engine's device space, like a plain
  `PNG_COLORSPACE_UNCALIBRATED` viewer. If a theme asset was authored
  assuming gamma correction, bake the correction into the pixels.
* **Out-of-range palette indices** — rendered as opaque black (spec permits
  an error; the decoder stays lenient rather than losing the whole image).
* **Chunk ordering violations** — e.g. PLTE after IDAT, or IHDR not first —
  are tolerated when harmless. A second IHDR is accepted and wins; the
  inflated-size check still rejects streams whose data does not match the
  final header. Strictness here has no security value: every read is
  bounds-checked against the final, validated header.
* **Missing IEND** — a warning; the stream decodes if the data is complete.
* **APNG / animations** — not PNG spec proper; only the base frame decodes
  (acTL/fdAT are skipped as ancillary chunks). Use the video layer for
  animated media.

## Malformed input and limits

Every malformed input is rejected with a specific error string — the
unit suite (`tests/test_png.c`) pins each one:

bad signature · chunk overruns the file · chunk CRC mismatch · no IDAT ·
palette image without PLTE · tRNS on RGB+A · zero or oversized dimensions ·
over-cap pixel count · invalid color type (1, 5, 7+) · bad depth/color-type
pair · unknown interlace method · filter type > 4 · inflated size mismatch ·
Adler-32 mismatch.

Hard limits:

* **Dimensions** — each side at most 16384 pixels, and at most
  100,000,000 total pixels (a 16384×16384 "image" is rejected as too
  large). A 100 MP RGBA16 file still needs ~800 MB transient + 400 MB
  image memory at decode time; the limit exists to bound a *hostile*
  file, not to encourage files anywhere near it. Wallpaper assets are
  typically ≤ 8 MP.
* **Decompression bombs** — the PNG decoder always knows the exact
  inflated size from the header, and passes it to the inflater as a
  **hard cap**: a 274-byte file claiming a 2×1 image but inflating to
  200,000 bytes is refused with `PNG: inflate failed: output too large`
  (`tests/fixtures/png_bomb.png`, generated by
  `scripts/mk_png_neg_fixture.py`). The pre-cap inflater grew the output
  geometrically before the size check ran; that path is gone.
* **Integer safety** — all row/scanline arithmetic is computed in 64-bit
  before any allocation; dimension multiplication cannot overflow.

## Encoding

`rev_png_encode` writes RGBA8 with filter byte 0 and **stored**
(uncompressed) DEFLATE blocks — valid PNG, minimal code, larger files.
It exists for tooling (`revtool mkpng`, `--once`/`--shot` output, test
fixtures), not for asset production; ship assets compressed with real
encoders (zopfli/mozjpeg-era tooling or simply `oxipng`).

## Where the decoder is used

* scene `image` layers (loose files and `.revpack` memory views),
* theme asset loading (`src/theme.c`),
* `revtool mkpng` fixtures and test oracles,
* every `--shot` / `--once` PNG the engine writes (encoder side).
